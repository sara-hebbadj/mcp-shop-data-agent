# Data: synthetic Lumi Skin shop database

**Everything here is synthetic.** Lumi Skin is a fictional skincare shop. No real company,
customer or order data was used. People are invented, emails use `@example.com` and phones
use the fake `+971 50 000 xxxx` pattern.

## How to build `shop.db`

```bash
python -m shop_data_mcp.generate_data          # writes data/shop.db (about 1.6 MB, 0.4 s)
```

`shop.db` is not committed: the generator rebuilds it byte for byte (seed 42, Python standard
library only). A test checks that a fresh build gives the same file and the same 50 gold answers.

## Sources

| File | Source |
|---|---|
| `lumi_skin/products.csv` | The 40 products from the shared synthetic Lumi Skin data, generated by `generate.py` (seed 42). Copied unchanged. |
| `shop.db` | Built by `src/shop_data_mcp/generate_data.py`. Name pools are copied from the same shared generator; customers, orders, returns and reviews are generated here at a larger scale. |

## Tables (snapshot taken at the end of 30 September 2026)

| Table | Rows | Notes |
|---|---|---|
| products | 40 | id, name, category, skin_type, key_ingredients, price_aed, stock |
| customers | 2,000 | **personal columns: full_name, email, phone, address**; city, country, language, signup_date |
| orders | 5,000 | 1 April 2025 to 30 September 2026; status, channel, payment_method, total_aed, destination, promised / shipped / delivered dates |
| order_items | 8,770 | order lines (qty × unit_price_aed = order total; White Friday 21–30 Nov 2025 is 20% off) |
| returns | 320 | returned lines with reason and refund |
| reviews | 1,956 | 1–5 star ratings with short comments in English, Arabic or French |

Built-in patterns, so the questions have something real to find: growth over time, peaks for
White Friday, December and Ramadan 2026, a summer dip, slower deliveries to Ras Al Khaimah,
Al Ain, Muscat and Jeddah, and higher return rates for the tinted sun cream, retinol and AHA products.

## Schema choices

- The customer name column is `full_name`, not `name` (the shared CSV uses `name`), so that
  every personal column name exists in only one table. The guard can then recognise personal
  data by column name alone.
- Orders have a `destination_city` and a `promised_date` (UAE: order + 3 days, other GCC: + 7 days)
  so delivery delay can be measured.
- `tracking_events` from the shared data is not included; it is not needed for these questions.
